## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on an incomplete task)
- **[Story]**: US1 / US2 / US3, mapping to the user stories in spec.md

## Path Conventions

Web app: `backend/jobforce/…`, `backend/tests/…`, `frontend/src/…`, repo-root `Makefile`, `CLAUDE.md`, `DEVELOPMENT.md`.

Backend commands run from `backend/` (`uv run pytest …`, `make check`). Frontend commands run from `frontend/`.

## Implementation Strategy

### MVP (US1 only)

Phases 1 → 2 → 3. The result is a checked-in, deterministic, drift-gated `openapi.yaml`, reviewable in diffs and readable by skills offline. Stop, run `make check`, and commit.

### Incremental Delivery

1. Setup + Foundational → renderer exists.
2. US1 → spec checked in and gated (**MVP**; commit).
