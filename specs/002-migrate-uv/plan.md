# Implementation Plan: Migrate Dependency Management to uv

**Branch**: `002-migrate-uv` | **Date**: 2026-05-27 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/002-migrate-uv/spec.md`

## Summary

Replace `pip install -e ".[dev]"` with `uv sync` across all project entry points. The existing `pyproject.toml` is already PEP 517-compatible and requires no dependency changes. The migration adds a `uv.lock` lockfile, updates both Makefiles and developer-facing docs, and removes the one remaining `pip install` reference in the root Makefile's `install` target.

## Technical Context

**Tool**: uv 0.9.9 (installed at `~/.local/bin/uv`)

**Build backend**: setuptools (existing, unchanged)

**Lockfile**: `uv.lock` — generated by `uv lock`, committed to version control

**Virtual environment**: `backend/.venv/` — created by `uv sync` (same path as current venv)

**Testing**: pytest via `.venv/bin/pytest` (Makefile already uses venv-relative paths)

**Project type**: Developer tooling migration — no source code changes, no new packages

**Constraints**:

- `pyproject.toml` dependency declarations MUST NOT change
- `.venv/` path convention MUST remain `backend/.venv/`
- `make check` MUST continue to pass without regression

## Phase 0: Research

**Skipped** — no NEEDS CLARIFICATION items. All decisions are known:

- uv 0.9.9 is installed and confirmed working (`which uv` returns path)
- `pyproject.toml` uses standard `[project]` + `[project.optional-dependencies]` — fully uv-compatible
- `uv sync` installs both runtime and `dev` extras by default when a `[tool.uv.dev-dependencies]` section exists, or via `uv sync --extra dev`; the correct invocation is `uv sync --extra dev`
- The `.venv/` location is controlled by uv's default (project root relative), so running from `backend/` places it at `backend/.venv/` — same as current

## Phase 1: Design

### Step 1 — Generate `uv.lock`

```bash
cd backend && uv lock
```

This reads `pyproject.toml`, resolves all dependencies (runtime + dev), and writes `backend/uv.lock`. The lockfile is committed to version control.

### Step 2 — Update `backend/Makefile`

Add a `sync` target and update the `dev` target to document the prerequisite:

```makefile
sync:
    uv sync --extra dev

dev:
    $(UVICORN) jobforce.main:app --reload --port 8000
```

`check`, `lint`, `typecheck`, `test` already use `.venv/bin/` paths — no changes needed there.

### Step 3 — Update root `Makefile`

Replace the `install` target:

```makefile
install:
    @echo "Installing backend dependencies..."
    @cd backend && uv sync --extra dev
    @echo "Installing frontend dependencies..."
    @cd frontend && npm install
```

Also update `seed` and `dev` targets to note that `uv sync` must run first (comment only — no functional change since `.venv/bin/` paths are already used).

### Step 4 — Update docs

**`README.md`** — Prerequisites section: add `uv` bullet, remove venv/pip mention. Setup section: replace `pip install -e ".[dev]"` with `uv sync --extra dev`.

**`specs/001-job-force-app/quickstart.md`** — Step 1 clone/install block: replace `pip install -e ".[dev]"` with `uv sync --extra dev`.

### Step 5 — Verify

```bash
cd backend && uv sync --extra dev   # install from lockfile
make check                           # all 65 tests pass, ruff + mypy clean
```

### No `data-model.md` or `contracts/`

This is a pure tooling change with no data entities or external API surface. Both artifacts are skipped per the plan template guidance ("Skip if project is purely internal").

## Implementation Strategy

All changes are non-breaking and can be validated in a single `make check` run. Suggested order:

1. Generate `uv.lock` (`uv lock` in `backend/`)
2. Update `backend/Makefile` — add `sync` target
3. Update root `Makefile` — replace `pip install`
4. Update `README.md` and `quickstart.md`
5. Run `make check` to confirm zero regressions
6. Commit all files including `uv.lock`
